# HTML/Canvas 场景：真实模型小试（设计 §12 第一条风险）

日期：2026-10-04。来源：实测，`claude -p`（本地 Claude 订阅登录），一次性夹具，未入库。对应设计 [多形态视频流水线](../design/2026-10-04-html-video-pipeline.md) §5、§12。

## 试验设置

- 夹具：一份提示词（`env` 契约 + 确定性规则 + 字体限制 + 看图自检要求）、金样本节选（`docs/temp/reel/reel.html` 的数学/形变/场景函数，约 300 行）、一份手写 `timeline.json`（3 个镜头、10 个旁白 beat，无节拍网格、无配乐）。
- 装配壳：把 `scenes/*.js` 包成 `{ draw(ctx, lt, env), pad? }` 模块，暴露 `window.renderAt(t)`；Playwright 无头 Chromium 取帧；`preview.py` 做静态检查 + 冒烟运行 + 16 个关键时刻拼缩略图。
- 任务：为一支中文知识讲解（"天空为什么是蓝的"，32.4 秒，1920×1080）写 3 个镜头。同一任务独立跑 3 次，agent 只能用 Read/Write/Edit 和预览脚本。
- 系统**不提供**缓动、粒子等库；`env` 只有尺寸、`cue(i)/cueEnd(i)/beats`、局部时间，`bt/bar` 在无网格时抛错。

## ✅ 已验证：agent 在无运行时库的前提下能稳定写出可运行的 Canvas 场景

| 项 | 3 次运行的结果 |
|---|---|
| 首次预览的静态/运行时报错 | 0 / 0 / 0（均一轮通过） |
| 逐帧确定性（38 个时刻，正序、倒序、全新页面三种渲染顺序） | 像素哈希全部一致 |
| 统一视觉语言、镜头间转场、字幕对齐旁白 | 三次都做到（光线与分子母题，用 `pad.in/out` 交叉叠化） |
| 看缩略图后自行发现并修复问题 | run3 发现波长标签放大后堆叠，加淡出后复查通过 |
| 耗时 / 轮数 / 折合 API 费用 | 11–14 分钟 / 19–34 轮 / $1.4–1.8（3 镜头、32 秒） |

- 三次都自己写了缓动、带种子的伪随机、弹簧、星芒等，并各自维护了 130–150 行的共用 `lib/`；金样本被当作技法参考，没有被照搬外观。
- 模块加载期用带种子的 PRNG 生成静态数组（例如星点位置）不破坏确定性；渲染期不应再消耗随机数。

## ⚠️ 暴露的问题（正式实现需要处理）

1. **时间硬编码**：run2 没有使用 `env.cue()`，把 beat 时刻写成字面量（`start = 8.2`），上游时间轴变化后会错位。其余两次分别有 16、19 处 `env.cue/beats` 引用。
   - 提示词要明确：所有时刻只能由 `env.cue/cueEnd/len` 推出，不许写字面秒数。
   - 校验器应做"重定时测试"：把 beats 整体平移后重渲染，帧应当跟着变。
2. **小字不可读**：角标、公式、波长标签（约 10px 的 Space Mono）在 1080p 下读不出来，三次都有。需要把字号下限的规则扩展到所有承载信息的文字，装饰性小标签单独说明。
3. **耗时和成本**：一次写 3 个镜头要 11–14 分钟；一部 20 个镜头的讲解会到数小时。需要按镜头分批、单镜头预览、风格与共用代码沉淀到 `lib/`。
4. **镜头边界**：run3 的 s1→s2 边界帧差偏大（均值差约 5.4，其余 ≤ 2）。预览可以加"边界帧差"提示。

## 夹具要点（复现用）

- 页面由系统组装：字体 `@font-face` + `window.__TIMELINE__` + `lib/*.js` + 每个镜头的包装脚本 + `global.js` + 运行时；`page.route` 在 `http://studio.local/` 下直接供给文件，不开端口。
- 运行时按镜头区间（含 `pad`）逐个 `ctx.save() → draw → ctx.restore()`，每个镜头之间重置变换、透明度、混合模式；镜头异常时包装成 `[scene <id> @lt=<秒>]` 加 JS 堆栈。
- `uv run --with playwright` 可直接复用本机 `~/Library/Caches/ms-playwright` 里的 Chromium（1243）。
- 静态检查先剥离注释再匹配禁用 API，避免注释里提到 `Math.random` 被误报。
