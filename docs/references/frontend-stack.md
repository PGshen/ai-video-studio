| ✅ | Vite 内置的 `http-proxy` 对 SSE 接口（`GET /sessions/{id}/stream`）确实不缓冲、逐块透传：本机起 `STUDIO_ENABLE_FAKE_RUNTIME=true`+临时 `STUDIO_DATA_DIR` 的后端和 `pnpm run dev` 的前端，创建项目/topic 阶段会话（`fake` 模型配置）后，先用 Python 的 `urllib.request` 打开 `http://127.0.0.1:5173/api/sessions/{id}/stream` 并给每一行打时间戳，再发一条消息——`turn_status`/`text`/`tool_call`/`tool_result`/`workspace_changed`/`snapshot` 全部在发消息后 ~80ms 内到达（fake 脚本本身跑得极快，事件之间没有可观测的间隔），但连接本身在事件到达后又存活了 7 秒多（其间收到 `sse-starlette` 的心跳注释行 `: ping - <时间戳>\r\n\r\n`）才被我们关闭——如果代理会缓冲到连接关闭才转发，事件应该在心跳之后才能读到，而不是提前 7 秒；另外用 `curl -N "...?after_seq=2"` 经代理重新连接，确认只回放 `seq=3/4` 两条，证明 `after_seq` 续传语义经代理也完好。验证脚本和完整 SSE 帧记录见 `.superpowers/sdd/m1-skeleton/task-12-report.md` | T12 实测（2026-09-27） |
| ✅ | TypeScript 6.0（本次安装的版本）里 `baseUrl` 已废弃（`TS5101`），`paths` 别名不再需要配 `baseUrl`（4.1+ 起 `paths` 可以独立生效，相对 `tsconfig.json` 自身的目录解析）；`tsconfig.json`、`tsconfig.app.json` 都只写 `"paths": {"@/*": ["./src/*"]}` | T11 实测（2026-09-27） |
| ✅ | ESLint flat config 用 `.ts` 后缀（`eslint.config.ts`）在 Node 24.11 下可以直接被 `eslint` CLI 加载，不需要额外装 `jiti` | T11 实测（2026-09-27） |
| ✅ | 前端分层规则（ARCHITECTURE §3）用 `eslint.config.ts` 里的 `no-restricted-imports`（`patterns`）实现，没有引入 `eslint-plugin-boundaries`；对 `src/components/ui/**` 和 `src/components/ai-elements/**` 单独放宽了格式类规则（`vue/multi-word-component-names` 等），因为这两个目录是 CLI 生成代码 | T11 实测（2026-09-27） |
