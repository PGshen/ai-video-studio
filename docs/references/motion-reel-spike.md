# 动态图形短片：真实模型小试（设计 §12 子项目 3 前置）

日期：2026-10-05。来源：实测，`claude -p`（本地 Claude 订阅登录，默认模型），一次性夹具，未入库。对应设计 [多形态视频流水线](../design/2026-10-04-html-video-pipeline.md) §5、§6.1、§12，补上 [html-canvas-agent-spike](html-canvas-agent-spike.md) 的"未覆盖"一条。

## 试验设置

- **时间轴**：128 BPM、8 小节、15.000 秒，4 个段落（intro / build / drop / outro），含 `grid`、8 个节拍脚本点（`moments`）。
- **A 画面（×2）**：agent 写 4 个镜头，`env` 在 2B 运行时之上补了 `bt/bar/hit/energy/moment`（`hit(name)` 为事件触发后约 0.18 秒衰减到 1/e 的包络）。事件、能量曲线是手写的，不是 B 的产物。工具 `./preview`：静态检查、冒烟运行、关键时刻缩略图（强拍、拍手、冲击加均匀采样）、确定性检查、"音乐整体平移 0.2 秒后关键帧是否变化"检查。Bash 只放行 `./preview`。
- **B 配乐（×2）**：agent 写 `music/compose.py`（只用标准库和 NumPy），输入 `STUDIO_TIMELINE`，输出 WAV 和事件 JSON。工具 `./render_music`：运行脚本，报指标（时长、峰值与削波、各段 RMS 与频谱重心、起音点与网格对齐率、声明事件与实测起音的匹配率），并画一张图（波形、频谱图、起音强度，叠加段落、小节线、事件标记）。Bash 只放行 `./render_music`。agent 只能用 Read 看图。
- 参考：金样本 `reel.html` / `audio.py`（技法参考）；提示词给出契约与音乐方向，没有给实现。

- 两次都把全部节拍时刻交给 `env.bt/bar/hit/moment`，字面量只用于相对时长（回弹持续 0.4 秒等）。上次小试暴露的"时间硬编码"在提示词明确禁止后没有再出现。
- 两次都做了统一母题（圆点 → 分裂 → 炸开 → 回收）、冲击前约半拍静默（0.234 秒，对齐网格）、转场踩在小节线上。看图后修了自己的问题。
- 自述不满意处都和肉眼所见一致：outro 中段偏薄或有凹陷、故障切片静帧像事故、节拍可见性依赖 HUD、riser 没有加速感。agent 能诚实指出缺陷，但没有靠自己补上。
- 观感只做了人工目视判断，没有量化。两个 DROP 起点的边界帧差分别为 201 和 67，是有意的闪白冲击，不是缺陷。

## ✅ 已验证：配乐（B）

| 项 | B1 | B2 |
|---|---|---|
| 耗时 / 回合 / 折合费用 | 28 分钟 / 74 / $7.41 | 29 分钟 / 73 / $6.69 |
| 时长、峰值、削波 | 15.000 秒、-1.0 dBFS、0 | 同左 |
| 整体 RMS | -11.7 dBFS | -12.0 dBFS |
| 各段 RMS（intro→build→drop→outro） | -22.2 / -12.8 / -7.8 / -13.5 | -18.3 / -11.6 / -9.3 / -13.1 |
| 实测起音落在 1/16 网格 30 ms 内 | 95% | 95% |
| 声明的起音类事件被实测起音命中（±40 ms） | 98% | 95% |
| 事件清单 | 131 条、8 个名字 | 136 条、8 个名字 |
| 自己换成 100 BPM / 19.2 秒重跑 | 时长与指标保持 | 同左 |

- **谱图加指标足以支撑迭代结构、节奏、动态**。B2 报告三处是看图改出来的：第一版 intro 其实不稀疏，drop 被 build 盖住；噪声类扫频造出离网格的假起音（对齐率 79% → 95%）；静默口不在网格上，被削掉了最后一记鼓点，改为"最后半拍"。
- 两个 agent 都主动做了 BPM 与总长变化的重跑，证明脚本跟着网格走。这个检查值得做成系统校验。
- 两个 agent 都明确说**听不到音色**：底鼓是闷是硬、混响是否过多、声像、和声是否动人，指标和图都测不出来。
- 7 条（B2）或 3 条（B1）声明事件对不上实测起音：t=0 处的事件（检测器没有前一帧，结构上测不到）、能量低于阈值的轻事件、被紧邻的冲击或下行扫频掩蔽的事件。

## ⚠️ 暴露的问题（正式实现需要处理）

1. **平移敏感度对短片没有区分力**：`global.js` 的 HUD 读 `env.bt/bar`，镜头平移后每一帧都变，62/62 恒成立。需要**逐镜头单独验证**（不含 `global.js`），并改成更强的检查：按比例改 BPM 后重渲染，关键事件时刻的画面应当跟着事件走。
2. **`env` 缺口**：`hit(name)` 只适用于 `onset` 事件，`kind=sweep`（riser、reverse）取不到起止；A1 只能用 `bar()` 自己推算。需要一个取事件起止的函数（例如 `env.span(name)` 返回列表）。`moment(i)` 的 `t` 是局部秒、`bt/bar` 也是局部秒，两个 agent 都用对了，文档里要写明。
3. **对齐率指标不是音乐性指标**：占位的"每拍一个底鼓"脚本也能得 97% 的匹配率；B1 为提高起音对齐率，给 riser 加了网格门限。需要在提示词里写明指标只证明对齐、不证明好听，并要求 agent 汇报"无法验证的部分"（两个 agent 都做到了）；画布要有播放器，音色由用户试听。
4. **起音检测的盲区**：t=0 与被掩蔽的事件会拉低匹配率，应当单独列出"检测不到但已声明"的事件，不要混进匹配率；对 `sweep` 类事件不计入。
5. **耗时与费用**：4 个镜头加一次配乐，各约 $7–11、30–45 分钟，是上次 3 个镜头 $1.4–1.8 的数倍（镜头更密、事件更多、迭代更多）。折合每镜头约 $2–2.7。20 个镜头的短片不现实，需要分段迭代、共用代码沉淀到 `lib/`。短片本身短（15–60 秒），影响小于讲解片。
6. **画面与音乐的真实联调没做**：A 用的是手写事件，B 的产物没有喂给 A，也没有真正试听配对。子项目 3 的集成测试要覆盖"B 的 `events.json` → 时间轴 → A 的 `env`"这条路径。

## 对子项目 3 设计的影响

- 设计 §5.1 的 `env` 契约（`bt/bar/hit/energy/moment`）可行，补 `span`/事件起止即可。
- 设计 §6.1 的 `render_music`（图 + 指标）可行；指标要拆成"对齐类"与"需要用户听"的两类，不把对齐率包装成质量分。
- 设计 §12 风险表"agent 听不到声音，合成配乐的音乐性"：结论为**结构、节奏、动态可以靠谱图迭代，音色必须依赖用户试听反馈**，不需要再加强指标。
- 重定时校验（改 BPM、改总长）应当进入 `render_music` 与 `validate_scenes_html`，两个 agent 已经自发在做。

## 3A 落地后对"暴露的问题"的处理（2026-10-05）

| 问题 | 落地 |
|---|---|
| 平移敏感度没有区分力 | `validate_scenes_html` 对短片逐镜头、装配时不含 `global.js` 做音乐平移检查（`probe.music_shift_sensitivity`，网格、事件、节拍脚本点、能量曲线整体后移 0.2 秒）；全部关键帧没变为错误，超过一半没变为警告；`lt` 与非零数字字面量比较有静态警告。真实 Chromium 用例验证了"读节拍的 `global.js` HUD 不能替镜头顶账" |
| `env` 缺口 | `env.span(name)` 取事件起止，`env.hit` 对 `sweep` 事件和未知名称报错并说明用法；`hit` 的衰减常数 0.18 秒 |
| 对齐率不是音乐性指标 | `render_music` 的文本分"对齐类"和"需要用户试听"，固定附一句试听提示；检测不到的事件（t=0 附近、与另一事件相距不足 40 ms）单独列出，不计入匹配率；`sweep` 不计分 |
| 脚本写死时间 | `render_music` 自动用 BPM×0.8（讲解：总长×1.25）重跑，时长、事件名、对齐率不对就拒绝并保持旧产物 |
| 耗时与费用 | 提示词要求逐镜头迭代；不加系统层限制 |
| 联调没做 | `tests/api/test_synth_music_flow.py` 的 `slow` 用例：真实沙箱里的 `render_music` 产物 → 时间轴 → 真实 Chromium 里每个 kick 起点 `env.hit('kick')` 为 1 |

另外两点是落地时才发现的：一是测试用合成底鼓若在 0.18 秒处被硬切会产生"第二个起音"，对齐率只有约 48%（平滑淡出后超过 90%），提示词和金样本里都写了"每个声音尾部要淡出"；二是 Seatbelt 沙箱拒读仓库根，而虚拟环境在仓库内，脚本 `import numpy` 失败，需要在 profile 里放回虚拟环境的读权限（`seatbelt_profile(..., allow_read=[sys.prefix])`）。

## 夹具要点（复现用）

- 时间轴由脚本生成：128 BPM，拍 `i × 60/128`，小节 1.875 秒；事件为每拍底鼓（冲击前 0.2 秒静默）、2/4 拍拍手、反拍镲片、`riser`（sweep，第 4 小节）、`impact`（第 5 小节起点）。
- 运行时是 2B `runtime.js` 的副本，仅替换 `hit/energy/moment` 三个占位；`assemble._RUNTIME` 指向副本。
- 配乐图用 `uv run --with matplotlib --with scipy`；生成的 `compose.py` 只依赖标准库和 NumPy。
- 起音检测：对数压缩谱流量，窗 2048、步长 512，局部峰值阈值 0.12；网格对齐按 1/16 拍 ±30 ms 统计。
