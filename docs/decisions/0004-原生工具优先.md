## 背景

起初考虑自己统一实现文件工具，以便集中控制权限。但这有额外的工作量，而且大概率不如 SDK 原生工具好用，会削弱 agent 的能力。

## 决定

- Claude 模型使用原生的 Read/Write/Edit/Glob/Grep/Bash/WebSearch/WebFetch。
- OpenAI 模型使用原生的 `ApplyPatchTool`、`ShellTool` 和托管 `WebSearchTool`。
- 其他模型（LiteLLM）使用兜底的最小文件工具集，以及接 Tavily 的搜索工具。
- 权限通过两道防线保证：事前拦截（尽力而为），加每轮结束时的越界检查（强制）。
- 业务工具只定义一次（`ToolSpec`），由适配层分别转换。

## 考虑过的其他方案

- **两种运行时都用自己实现的文件工具**：不选的原因：削弱能力，还有额外工作量。

## 影响

不同运行时的 agent 行为不完全一致，这是可以接受的，因为引入两种运行时是为了扩大模型的选择面。风险项 R1–R3 需要在 M1 验证。
