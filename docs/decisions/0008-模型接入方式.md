## 背景

负责人希望 Claude 既能用 API key，也能用本机已登录的订阅账号；Anthropic API 需要经自建网关，OpenAI 经 OpenRouter 接入。

## 决定

- 模型配置的 `api_key_env` 为空表示 Claude 本机登录模式：不注入 key，并置空子进程继承的 key 与宿主变量；成本只作参考，步数上限照常强制。官方文档对第三方产品使用 claude.ai 登录有限制，负责人已知悉并自行判断。
- 网关通过 `STUDIO_ANTHROPIC_BASE_URL`、`STUDIO_OPENAI_BASE_URL`、`STUDIO_OPENAI_MODEL`、`STUDIO_OPENAI_PRICE_INPUT/OUTPUT` 配置，种子写入并受控更新对应字段。
- OpenAI 配置指向非官方主机（如 OpenRouter）时：不提供 Shell（OpenRouter 不支持在本地工作区执行），请求设 `store=False` 并回传 reasoning 加密内容；型号须支持 `apply_patch`（gpt-5 不支持，M1 选用 `openai/gpt-6-luna`）。
- 模型配置的 `supports_vision=false` 时，业务工具的图片结果只把文字发给模型（DeepSeek 实测不支持图片）。

## 考虑过的其他方案

- **OpenRouter 改用 Chat Completions + 兜底文件工具**：不选的原因：实测 Responses API 与 `apply_patch` 在 OpenRouter 上可用，保留原生工具能力更强。

## 影响

更换 OpenAI 型号时要确认它支持 `apply_patch`；已有数据库的种子行不会自动改 `supports_vision` 与单价以外的字段，见 dev-setup「已知限制」。
