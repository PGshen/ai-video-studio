# 0020：阶段流水线按项目配置派生

## 元信息

| 项 | 值 |
|---|---|
| 状态 | 提议 |
| 日期 | 2026-10-04 |
| 相关 | [多形态视频流水线设计 §2–§3](../design/2026-10-04-html-video-pipeline.md)、[架构设计 §1/§5](../design/2026-09-26-architecture.md)、[ADR 0005](0005-渲染并入动画阶段.md)、[ADR 0017](0017-一张选题可以创建多个项目.md) |

## 背景

已批准的架构设计把流程固定为"选题打磨 → 叙事 → 动画"，上下游关系由各 `StageDefinition.upstream_stages()` 静态声明。现在要支持多种视频形态（Manim/HTML 讲解、动态图形短片、音乐 MV），它们的阶段集合和顺序都不同：无旁白的形态需要"创意""节拍脚本"替代"选题""叙事"，有配乐的形态需要"配乐"阶段，而且配乐在 MV 里排在节拍脚本之前、在短片里排在之后（谁定时间谁在前）。静态上下游无法表达同一个阶段在不同项目里有不同上游。

## 决定

- 创建项目时选择视频类型：`projects.settings` 新增 `video_kind`、`engine`、`narration`、`music_source`，以及由纯函数 `build_pipeline(config)` 派生的 `pipeline`（阶段 key 列表）。这些字段创建后锁定。
- 阶段按变体拆成不同 key（`topic`/`concept`、`narrative`/`beatsheet`、`animation`/`animation_html`，另增 `music`），界面共用显示名；现有 key 不变。
- `StageDefinition.upstream_stages()` 改为 `reads()`（可能读取的阶段）；实际上游由 `agent` 层的 `upstream_of` 用 `reads()` 与项目流水线取交集、只保留排在前面的阶段得出。定稿/stale、`upstream/` 刷新、回退建议、前言都改用它。
- `StageDefinition` 新增可选钩子 `prepare_turn(workdir)`，每轮刷新 `upstream/` 后调用，用于生成只读派生文件（如 `upstream/timeline.json`）。
- 缺新字段的老项目视为 Manim + 旁白 + 无配乐，流水线 `[topic, narrative, animation]`，不迁移数据。

## 考虑过的其他方案

- **一个阶段内按配置分支（例如 `narrative` 带"旁白/节拍"两种模式）**：不选的原因：提示词、工具、校验器、产物 schema 都会出现大量分支，单一职责被打破。
- **配置可在创建后修改**：不选的原因：引擎和阶段序列决定了产物格式，中途修改等于重做；ADR 0017 已允许一张选题建多个项目，换类型新建项目即可。
- **把配乐塞进叙事阶段或作为旁路资产**：前者让叙事阶段职责膨胀且 MV 的"先有音乐"别扭；后者失去定稿点与 stale 传播。

## 影响

- 取代架构设计中"固定三阶段"和"静态上下游"的前提；已批准设计不改，以本 ADR 和新设计文档为准。
- `stage_flow`、TurnRunner 的上游刷新、`suggest_upstream_change`、前端 `StageNav` 都要改为读项目流水线。
- `db/repo/settings.py` 的 `STAGES`（各阶段默认模型）需要加入新阶段 key。
- 新阶段的 import-linter `independence` 契约需要扩展。
