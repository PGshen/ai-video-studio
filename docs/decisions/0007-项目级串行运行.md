# 0007：同一项目同一时刻只运行一个 turn

## 元信息

| 项 | 值 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-09-28 |
| 相关 | [M1 计划](../plans/completed/m1-skeleton.md)、[架构设计 §4.3、§4.4](../design/2026-09-26-architecture.md) |

## 背景

三个阶段（选题、叙事、动画）共用一个工作区。设计 §4.4 只规定"同一会话同一时刻只允许一个运行中的 turn"。M1 实现 TurnRunner 时发现：如果同一项目里两个阶段的 turn 并发，一方轮末的越界检查会把另一方的合法写入当作越界还原，快照也会混入对方的中间状态。

## 决定

- TurnRunner 按项目串行：同一项目已有运行中的 turn 时，新 turn 进入 `queued`，按 FIFO 启动；全局并发上限另算。
- 写工作区的 API（保存文件、回滚、定稿、重新打开）在项目忙时返回 409；这些端点是 `async def`，忙检查与写入之间没有 await，相对调度器是原子的。
- 项目详情接口提供 `busy` 字段，前端据此把画布和"回滚到此"置为只读。

## 考虑过的其他方案

- **按阶段划分工作区锁**：不选的原因：越界检查基于整个工作区的扫描差异，按目录加锁需要重写 guard 和快照逻辑。
- **只按会话串行（设计原文）**：不选的原因：会出现上面描述的相互还原。

## 影响

单人使用时多个阶段不能同时对话，影响很小。以后若需要并行，要先把快照和越界检查改成按阶段目录进行。
