# 0022：风格目录允许二进制截图，第一张作为封面

## 元信息

| 项 | 值 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-10-08 |
| 相关 | [计划 style-screenshots](../plans/completed/style-screenshots.md)、扩展 [ADR 0019](0019-风格库改用磁盘目录存储.md) |

## 背景

风格库卡片只有文字，用户要点进去读文件才知道一套风格画面长什么样。需要给每套风格保存几张截图，第一张作为封面。ADR 0019 的风格目录只有 `STYLE.md`、`references/`、`exemplars/` 三项，且全是 UTF-8 文本（`StyleFiles = {路径: 文本}`）。

## 决定

- 风格目录（正式版本和草稿）新增 `screenshots/` 子目录，放二进制图片。文件名由服务端生成：`<三位序号>-<内容 sha256 前 12 位>.webp`，按文件名排序就是显示顺序，第一张是封面；不另建索引文件，目录是唯一的事实来源。
- 上传时用 Pillow 识别实际格式（只收 PNG/JPEG/WebP），校正 EXIF 方向，长边缩到 ≤ 1920，统一存成 WebP。单张原始文件 ≤ 10 MB、像素 ≤ 5000 万，每套风格最多 12 张。
- `StyleFiles` 仍然只装文本：读目录的函数跳过 `screenshots/`，截图由 `studio.styles.screenshots` 和 `store` 里的专用函数处理。因此校验、`validate_style` 工具、导入脚本、创建项目时复制到 `style/` 都不受影响——截图不会进项目工作区；agent 的可写范围不变（`references/*`、`exemplars/*`、`STYLE.md`），但它的工作目录就是草稿，`screenshots/` 对它是可见的，所以风格对话的提示词明确写了「不要读、改、删」，每轮结束的清理也只删 `screenshots/` 里不合法的条目。Bash 在沙箱里对草稿目录可写、没有越界还原，因此这是提示词约束而不是强制保证：agent 若误删了草稿里的截图，用户可以「放弃修改」回到正式版本。
- 截图和文本走同一套草稿流程：打开草稿时一起复制，保存时一起原子装进正式版本，放弃时一起丢弃；`dirty` 也把截图算进去。复制风格带上截图，删除风格一并删除。

## 考虑过的其他方案

- **截图存在草稿流程之外，上传和删除立即生效**：改动小，但「放弃修改」撤不回截图，同一屏上文本和截图的行为不一致。负责人选择走草稿流程。
- **把截图当成 `StyleFiles` 里的 base64 文本**：体积膨胀三分之一，每次读写整包都带着图，agent 的 Read 也会读到一大段无用文本。
- **文件名不带哈希，另存 `order.json`**：多一个要保持同步的文件；带哈希的文件名还能让浏览器缓存。

## 影响

- 风格目录不再只有文本：任何以后遍历风格目录的代码都要决定怎么对待 `screenshots/`（默认应当跳过）。
- 截图只用于风格库里浏览和识别风格，不参与创建项目；以后想让 agent 参考截图是新的决定（需要改项目 `style/` 的复制规则和提示词）。
- 没有降级需要处理：旧风格没有 `screenshots/` 目录，一切照常。
