# 0017：一张选题卡片可以创建多个项目

## 元信息

| 项 | 值 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-10-03 |
| 相关 | [架构设计 §3.1](../design/2026-09-26-architecture.md)（`ideas` 表）、[计划 M4](../plans/completed/m4-topic.md) |

## 背景

M4 的设计里，从想法卡片创建项目会把卡片置为 `picked` 并写入 `ideas.project_id`，之后卡片不能再创建项目、不能归档、不能改标题。负责人使用后希望同一个选题能反复创建项目（换风格、换切入角度各做一版），选题池里的「打开项目」也要能跳到项目列表并按该选题筛好。

## 决定

1. 卡片和项目的关联只记在 `projects.idea_id`（一对多）。去掉 `ideas.project_id` 列和 `picked` 状态；卡片状态只剩 `idea` / `archived`。
2. `POST /api/projects` 带 `idea_id` 时，卡片只需存在且不是 `archived`；创建项目不改变卡片。并发抢卡片的条件更新（`mark_picked`）随之删除。
3. 卡片的标题、归档不再因为「已创建项目」而受限；项目工作区里的 `topic/notes/idea-card.md` 是创建时的副本，之后改卡片不会同步。
4. 迁移 `0005`：`picked` 的卡片改回 `idea`，删除 `ideas.project_id`（信息已在项目的 `idea_id` 里）。降级只补回空列，`picked` 状态无法还原。
5. 前端：选题卡片显示「已创建 N 个项目」（N 由项目列表按 `idea_id` 统计，`IdeaOut` 不带项目信息）；「打开项目」跳转 `/projects?idea=<id>`，项目列表按这个参数筛选。

## 考虑过的其他方案

- **保留 `picked`，只放开创建限制**：状态和事实不一致（`picked` 后仍可再创建），不选。
- **`IdeaOut` 增加 `project_ids` / `project_count`**：每次列选题都要联表；前端本来就要拿项目列表，直接统计即可，不选。

## 影响

- 架构设计 §3.1 表格里 `ideas` 的 `status`、`project_id` 描述已过时，以本 ADR 为准（已批准的设计文档不直接改）。
- 头脑风暴 agent 的 `list_ideas` 不再有 `picked` 状态；`update_idea` 只拒绝 `archived` 的卡片。
