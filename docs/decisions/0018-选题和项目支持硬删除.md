# 0018：选题和项目支持硬删除

## 元信息

| 项 | 值 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-10-03 |
| 相关 | [M4 选题计划](../plans/completed/m4-topic.md)（原写「不提供 DELETE」）、[ADR 0017](0017-一张选题可以创建多个项目.md) |

## 背景

M4 时选题只能归档、不能删除；项目没有对外的删除接口。用了一段时间后，试错留下的选题和项目越积越多，
列表被噪音占满，归档也解决不了「这个项目就是不要了」。

## 决定

- 新增 `DELETE /api/ideas/{id}` 和 `DELETE /api/projects/{id}`，都是**硬删除**，不可恢复；选题仍然保留「归档」作为可恢复的选项。
- 选题已经创建过项目时返回 409，要先删项目。这样不会出现项目指向一张不存在的选题。
- 删除项目会清理：工作区目录，以及快照、阶段、会话（含轮次和事件）、回退建议、任务的记录。项目有运行中的 turn 或 `queued`/`running` 的任务时返回 409。
- `BlobStore` 里的内容不删：它按内容寻址，可能被其他项目的快照共用，留下孤儿内容不影响正确性。
- 选题页和项目页的卡片内各有一个删除按钮，点击后弹确认框，409 的原因显示在确认框里。

## 考虑过的其他方案

- **软删除（打标记）**：可恢复，但所有查询都要过滤，工作区文件也还占着磁盘；归档已经覆盖了「可恢复」的需求。
- **删选题时连带删除它的项目**：一次点击就能删掉大量工作成果，风险太高。

## 影响

- 选题的头脑风暴会话（`source_session_id`）不随选题删除，保持原样。
- 删除项目后孤儿 blob 不会回收；如果磁盘占用成为问题，需要单独做一次基于引用的垃圾回收。
