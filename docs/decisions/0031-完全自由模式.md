## 背景

自由模式（ADR 0029）虽然不分阶段，仍带着格式契约：短片必须配乐，镜头按 `animation/shots.json` + 场景脚本的固定结构写，要经过 `validate_scenes_html`、`render_preview_html`，成片由 worker 按固定文件位置渲染，系统提示词里有大段交付约定。负责人想要"像直接用 Claude Code 一样"在工作区里随手做东西：没有结构、没有检查、没有阶段提示词。

约束：阶段协议的 `system_prompt()` 只能返回一段字符串，Claude 运行时把它当作完整系统提示词传给 CLI（会替换掉 Claude Code 默认提示词）；三个运行时的命令执行都在断网的沙箱里（ADR 0009/0024），装依赖、下载素材做不到。

## 决定

1. **第三种 `mode="open"`、单阶段 `open`**：`OPEN_KIND = ProjectKind("html", False, "none", "open")`，形态字段只是占位，代码一律按 `mode == "open"` 分支；创建时不接受形态字段，另收可选 `theme`。工作区初始只有 `style/**`、顶层 `project.md`（标题、主题、风格引用、技术栈优先级）与 `TECH-STACKS.md`（常见视频技术栈参考，优先级最低，2026-10-17 补充）。
2. **`StageDefinition.system_prompt() -> str | None`**：`None` 表示用运行时自己的默认提示词、不追加内容。Claude 用 `{"type": "preset", "preset": "claude_code"}`；OpenAI Agents SDK 的 `instructions=None`；Codex 不传阶段指令，只保留"不要派生子 agent"一句（这个 codex 版本关不掉协作工具）。现有阶段都返回字符串，行为不变。
3. **`StageDefinition.exec_network: bool`**：只有 `open` 为真。命令可以访问外网，但**一律不能访问本机回环**：本机的 studio API（`127.0.0.1:8000`）没有认证，连上就能读别的项目、改模型配置让后端把 API key 发出去（分支评审发现，2026-10-16）。
   - Claude：沙箱加 `network.allowedDomains=["*"]` 与 `deniedDomains=[localhost, 127.0.0.1, ::1, 0.0.0.0]`（实测：CLI 的网络代理本来就连不上回环，显式拒绝是纵深防御；外网 200）。
   - OpenAI Shell：Seatbelt 把 `(deny network*)` 换成拒绝 `(remote ip "localhost:*")` 与全部 unix socket，只放回 mDNSResponder 的 socket（DNS）；LaunchServices/Apple Event/`open`/`osascript` 三条逃逸规则保留。真实执行测试：回环（127.0.0.1、localhost、127.0.0.2）失败，外网成功。
   - Codex：**不放开**。`permissions.<profile>.network.enabled=true` 会连回环一起放开，`domains` 拒绝规则只在实验性的网络代理模式下生效（实测无效），于是失败关闭——Codex 下完全自由阶段的命令仍断网。这是相对设计 §5.2 的收窄。
   - 三者的读隔离（拒读仓库、数据目录、凭据目录）与写隔离都不变；`exec_mode` 与「无隔离执行」开关不变。命令可联网时，npm/pip/XDG 缓存目录指向工作区 `.cache/`（沙箱只许写工作区，默认的 `~/.npm` 会 EPERM；`.cache/` 不进快照）。
4. **只给一个自建工具 `tts`**：文字 → mp3，写到 agent 指定的工作区路径；密钥在后端，agent 自己做不了。工具描述就是它的说明。Claude 的内置工具沿用现有显式列表，不用 tools preset（本机 CLI 的 preset 名单里没有 Glob/Grep，多的是依赖宿主 UI 的工具）。
5. **整个工作区可写**，`style/`、`project.md` 也可改；只有 `uploads/` 与系统目录受保护。任意深度的 `node_modules`、`.venv`、`__pycache__` 不进快照、不列进文件树、guard 与回滚都不碰（对所有项目生效）。
6. **完成即定稿**：给 `open` 阶段定稿同时标记项目完成，重新打开清除；没有前置检查。渲染任务与 `finalize-render` 对 `open` 项目返回 409。画布只有 `FileCanvas`，HTML 文件可以在 `sandbox="allow-scripts"` 的 iframe 里预览。

## 考虑过的其他方案

- **放宽现有 `free_produce`**：提示词、工具、定稿检查、时间轴来源都与格式契约绑在一起，开关会散落各处；阶段协议不带项目参数，一个阶段名只能有一套提示词。不选。
- **脱离阶段系统的裸会话**：同 ADR 0029 的理由，会话、快照、路由都以阶段为单位，改动遍布全栈。不选。
- **系统提示词传空串**：Claude 会失去 Claude Code 默认提示词里的工具用法与工作习惯，体验比终端里的 Claude Code 差很多。负责人选择用 preset。
- **完全不隔离（不传 sandbox）**：与 ADR 0009/0024 的失败关闭原则冲突，能读本机任意文件。负责人选择保留隔离、只放开网络。
- **Bash 联网用域名白名单**：实测 `"*"` 可行，白名单维护成本高、也挡不住借白名单域名外发。不选。

## 影响

- 好处：完全自由项目的对话体验接近在终端里用 Claude Code 操作同一个目录；产物结构不受限制；快照、回滚、附件、多运行时都照常可用。
- 代价与残余风险：`open` 阶段里提示注入后，命令可以把**工作区内**的内容外发（读隔离仍挡住仓库、数据目录、凭据目录和其它项目；回环被拒，碰不到本机 API）。如果用户把后端绑到非回环地址（`Settings.host`，环境变量 `STUDIO_HOST`），沙箱能经局域网地址访问它——不要这样部署，或在那之前给 API 加认证；Codex 下完全自由阶段装不了依赖（失败关闭）；agent 可能改坏 `style/`、`project.md`（可回滚）；视频等大文件反复生成会让快照库增长（TD-98）。`html-preview`、场景检查等接口对 `open` 项目没有意义：前者因没有时间轴返回 409，后者返回"未检查"。
- 之后：新阶段若想用运行时默认提示词或命令联网，直接设 `system_prompt() -> None`、`exec_network = True`；运行时升级后重新核对 preset 工具名单、`allowedDomains` 通配、Codex 网络配置键（references 里记了验证版本）。
