## 背景

架构设计把整个 `data/` 加进 `.gitignore`：数据库、快照内容、项目工作区都是个人运行数据，不该进仓库。但风格库（`data/styles/`）是从旧项目导入并持续打磨的基础资产，换一台机器或别人克隆仓库时也需要它；只放在本地意味着丢了就没了，也没法共享。

ADR 0019 之后，一套风格就是 `data/styles/<id>/` 一个目录（`STYLE.md`、`references/`、`exemplars/`、`screenshots/`），`studio.styles.store` 不依赖数据库，所以这个目录可以单独入库，克隆下来即可使用。

## 决定

- `.gitignore` 从 `data/` 改成 `data/*` + `!data/styles/`：只放开风格库**正式版本**。
- 同时忽略 `data/styles/.*.tmp-*/` 和 `data/styles/.*.old-*/`：这是 `_install`/`_swap` 被打断时留下的半成品与备份，启动时由 `recover_interrupted_swaps` 收拾，不入库。
- 其余继续忽略：`style-drafts/`（编辑中的草稿）、`studio.db*`、`blobs/`、`projects/`、`scratch/`、`claude/`（agent 运行时状态）、`tts-preview/`（试听缓存）、`evidence/`、`legacy-export/`。
- 设计文档 §2 目录结构里「`data/` 加入 .gitignore」的注释按本 ADR 理解为「除风格库正式版本外」；设计文档本身不改。

## 考虑过的其他方案

- **风格库挪到仓库里的独立目录（如 `assets/styles/`），`data/styles` 只做运行时副本**：要新增同步或初始化逻辑，两份内容容易不一致。不选。
- **同时放开 `evidence/` 的文本部分（约 2.2 MB）**：`docs/` 有上百处链接指向它，入库能修复断链；但它是验证过程的产物，量会随计划持续增长，媒体文件还得逐类排除。先不做，需要时另行决定。
- **放开 `legacy-export/styles.json`**：风格已经导入并入库，它只剩备份价值。不选。

## 影响

- 在界面里保存风格会在 `git status` 里出现改动，需要手动提交；草稿不会出现。
- 风格目录的 id 是随机的 uuid hex，不同机器各自新建的风格不会冲突；同名风格由应用层的唯一性校验处理。
- 用环境变量把数据目录改到仓库之外时，应用不会读到仓库里的这份风格库，需要自行复制过去。
- 风格对话的 agent 工作目录是 `style-drafts/` 下的草稿，仓库的 `.git` 本来就在 `data/` 的上层，本决定不改变 agent 能看到的东西；§3.3「工作区里不用 git」的约束不受影响。
