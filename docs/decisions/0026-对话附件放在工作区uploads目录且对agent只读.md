## 背景

对话框要能上传文件交给 agent 读。文件得放在 agent 读得到的地方（Claude 的 Read 只能读工作区内），又不能让 agent 改掉用户给的原始资料。上传发生在一轮开始之前，而每轮结束时的越界检查会把“本轮期间出现在可写范围之外的改动”还原，同一项目里别的会话正在跑的那一轮会把新上传的文件当越权改动删掉。

## 决定

- 非图片附件写到工作区 `uploads/<请求短 id>-<安全文件名>`；图片进 `BlobStore`，作为多模态输入发给模型。
- `workspace.scope.is_writable` 对 `uploads/` 一律返回 False，不依赖各阶段的 `WriteScope` 声明；所以写工具直接拒绝，Shell 改动在轮末被还原。`uploads/` 进快照，随回滚还原。
- 风格对话的工作目录是草稿目录（没有快照和越界还原）：`prune_draft` 和保存时跳过 `uploads/`，保存成正式版本不带过去，草稿删除时一起删掉。`styles` 不能依赖 `workspace`，目录名在 `styles/layout.py` 另写一份，由测试保证一致。
- 项目里有别的会话的一轮正在运行，或者正在上传音乐时，会写工作区的附件消息返回 409；只带图片的消息照常排队。

## 考虑过的其他方案

- **附件放在工作区之外**（例如 `data/uploads/`）：不选，Claude 的读范围 hook 只允许工作区内，要为附件单独开读权限。
- **在各阶段的 `WriteScope` 里逐个排除 `uploads/`**：不选，容易漏掉以后新增的阶段。
- **上传时不检查项目忙**：不选，正在跑的那一轮结束时会静默删掉刚上传的文件。

## 影响

- 以后新增阶段不需要为 `uploads/` 做任何声明。
- 时间线里的文件附件只下载、不在应用源上直接打开，避免上传的 HTML/SVG 以应用身份执行脚本。
- 大 PDF 读不了的限制见 TD-88。
