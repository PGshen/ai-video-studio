## 背景

设计 §1 写的是「运行时由所选模型决定，会话中途不切换」。使用者在批准 M5 时提出：对话进行中想把模型换成**同一供应商**的另一个（例如先用便宜的模型摸方向，再换强的模型精修，对话记忆保留）。

约束：会话的记忆存在 SDK 那边（Claude 的 transcript，`sdk_ref`；OpenAI 的 `SQLiteSession`），换模型不能丢；`TurnRunner` 每轮开始时本来就按 `session.model_profile_id` 重新读配置，所以底层几乎不用动；成本和预算按每轮实际用的配置计算。

## 决定

新增 `PATCH /api/sessions/{id}`（`{"model_profile_id": ...}`），把会话换成另一个模型配置，从下一轮起生效。

**允许条件**（都不满足返回 400，会话有排队/运行中的 turn 返回 409）：

1. 目标配置存在，它的运行时已启用，密钥已配置；
2. 与当前配置**同 `runtime` 且同 `provider`**；
3. Claude 运行时另外要求**同一种认证方式**（`api_key_env` 相同：都是本机登录，或者同一个环境变量）。

**只改** `sessions.model_profile_id`：`runtime`、`sdk_ref`、`is_active` 和历史都不动。

**每轮记录实际用的模型**：`turns.usage` 增加 `model` 和 `profile_name`（无迁移，`usage` 是 JSON）。**换了之后的第一轮**开头，`TurnRunner` 把本轮配置和会话上一轮实际用的（`usage.profile_name`，不是「被改过几次」）比较，不同就发一条 `notice`（`kind=model_switched`，落库、可回放）。连续换两次又换回原来那个不提示；第一轮、M5 之前的旧 turn（没有 `profile_name`）不提示。

## 考虑过的其他方案

- **不允许换，要换就新建会话**：不选的原因：新会话没有对话记忆，靠交接摘要兜底效果差；使用者明确要求保留记忆。
- **允许跨供应商、跨运行时**：不选的原因：Claude 的 transcript 和 OpenAI 的 `SQLiteSession` 互不相通，换运行时等于丢记忆；跨供应商的工具调用格式、图片能力也不同。
- **Claude 登录 ↔ API key 也允许互换**：暂不选。SDK 会话存储位置随认证方式而变（登录模式在 `~/.claude/projects/`，API key 模式在 `<data_dir>/claude/projects/`，见 claude-agent-sdk.md 的 R4 两行），互换后 `resume` 能否找到 transcript 没有验证过；验证需要用 API key 发付费请求，计划只预先授权了本机登录的冒烟。所以先按最保守的规则限制，验证之后可以放宽（见下）。
- **换模型时发一条前言给 agent**：不选的原因：`notice` 只给人看；agent 的上下文里本来就是同一段对话，换的只是背后的模型，不需要告诉它。

## 影响

- **实测（2026-09-30，本机 Claude 登录）**：同一个 SDK 会话第一轮用 `claude-sonnet-5`、第二轮换成 `claude-haiku-4-5-20251001`（同一登录下另一个模型配置），`sdk_ref` 不变，第二轮正确复述了第一轮收到的背景，时间线上有一条 `model_switched` 的 `notice`。证据 `data/evidence/m5-polish/smoke/20260930T132106Z-model-switch-claude-login.json`；用例 `make smoke SMOKE_ARGS="-k model_switch_claude_login"`。
- OpenAI 路径只有 mock 测试：`SQLiteSession` 的历史与模型无关，没有实机验证。
- **待验证（登记为 TD-41）**：Claude 登录 ↔ API key 互换。验证方法：用一个带 `ANTHROPIC_API_KEY` 的配置和 `claude-login` 各跑一轮同一个会话，看第二轮能否续上；需要 SOP §6 第 7 条事先同意。通过后把第 3 条限制删掉。
- 换模型后每轮的成本仍按该轮实际配置计算；Claude 的成本账本按 SDK 会话 id 记账，换模型不新开 SDK 会话，账本不受影响；价格不同的两个配置之间，`cost_usd` 是各轮各自的值。
- 偏离设计 §1 的「会话中途不切换」（设计文档按红线不修改，本 ADR 记录偏离）：只放宽到同 runtime、同 provider 内，运行时仍然由所选模型决定、不跨运行时切换。
