# 0002：用 SQLite 和本地文件，去掉 Temporal、Postgres、MinIO

## 元信息

| 项 | 值 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-09-26 |
| 相关 | [架构设计 §2、§3](../design/2026-09-26-architecture.md) |

## 背景

系统由一个人在本地使用。对话式流程下，阶段状态就是"会话 + 定稿快照"，不需要长流程编排。

## 决定

- SQLite（WAL 模式，`busy_timeout=5000`，只用短事务）作为唯一的数据库。
- 文件直接放在本地数据目录。
- 两个进程：`api`（FastAPI + agent 会话 + 预览渲染）和 `worker`（成片渲染），只通过 SQLite 和数据目录通信。
- 服务只绑定 127.0.0.1，不做鉴权。

## 考虑过的其他方案

- **保留 Postgres，用 LISTEN/NOTIFY 推送事件**：不选的原因：api 和 agent 在同一进程，事件在内存中直接推送就够了。
- **api 与 agent runner 分成两个进程**：不选的原因：会多一层跨进程事件传递。热重载打断 agent 的问题，通过限定 reload 监听目录和 `interrupted` 恢复机制解决。

## 影响

几乎没有外部依赖。代价是：api 重启会中断正在运行的轮次（可以恢复）；SQLite 不适合以后扩展到多人。
