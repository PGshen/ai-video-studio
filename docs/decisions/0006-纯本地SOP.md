# 0006：采用 AI 主导、纯本地运作的开发流程

## 元信息

| 项 | 值 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-09-26 |
| 相关 | [SOP.md](../SOP.md) |

## 背景

后续开发希望大部分工作由 AI 完成，同时使用 Claude Code 和 Codex；不需要远程 PR 和 CI。

## 决定

- `AGENTS.md` 作为入口地图，`CLAUDE.md` 只引用它。
- 计划文件同时作为交接文件。
- 人只在三个关口介入：批准设计、批准计划、验收。
- `make check` 是唯一的质量关口：pre-commit 运行 `check-fast`，合并前在合并后的代码上运行完整的 `check`。
- 每份计划一个分支，以 `--no-ff` 合并到本地 main。

## 考虑过的其他方案

- **GitHub PR 加 Actions**：不选的原因：一个人使用，本地关口就够了。

## 影响

纪律完全靠本地 hook 和 `make check` 维持，所以要尽量把约定改成机器检查（SOP §10）。
