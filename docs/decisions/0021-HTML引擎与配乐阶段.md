## 背景

已批准的架构设计规定"保留引擎接口，第一版只实现 manim"，成片音频只有逐镜头配音。探索作品（`docs/temp/reel/`）验证了 Canvas 2D 纯函数画面 + NumPy 合成配乐 + Playwright 逐帧导出的做法：确定性、预览与导出一致、出帧快，并且支持以音乐节拍为时间轴的无旁白视频。要把它融入系统，需要第二个渲染引擎、一份与时间来源无关的时间轴，以及配乐的生产环节。

## 决定

- **HTML 引擎** `engines.render.html`（纯能力层）：组装页面、`renderAt(t)` 契约，Playwright + 无头 Chromium 逐帧取图经 ffmpeg 编码为无声视频。只支持 Canvas 2D；场景按段拆文件（`animation/scenes/<id>.js`），段间无共享可变状态；用静态检查 + 冒烟运行保证确定性。
- **不提供绘图运行时库**：系统只提供挂载壳和 `env` 中的时间轴取数函数；技法由 agent 自由编写，项目内复用放 `animation/lib/`，需要起点时用风格库金样本。
- **统一时间轴** `studio.timeline`（纯能力层）：把旁白配音、节拍脚本、音乐分析、音乐事件合并为 `timeline.json`（预留歌词层），由消费阶段在 `prepare_turn` 中生成到 `upstream/`。Manim 路径不变。
- **配乐阶段** `music`：合成形态由 agent 写 NumPy 脚本（只约定输入输出环境变量），工具运行并返回频谱图与指标供自检；导入形态由 librosa 分析拍点/强拍/段落/能量，agent 在 `sections.json` 中修正分段。
- **成片**：worker 新增音频混合步骤（旁白拼轨、背景乐侧链压低、MV 截取），缓存键与 `final.json` 纳入时间轴哈希和音频源。
- **新依赖**：`playwright`（`make setup` 安装 Chromium）、`librosa`。

## 考虑过的其他方案

- **提供运行时库（缓动、形变、粒子、后期）**：减少 agent 重复劳动，但会把技法限制在库的 API 内、不同风格被拉平。负责人决定不提供，改用金样本。
- **DOM/CSS 动画或 WebGL**：CSS 动画无法按任意 `t` 精确定位，WebGL 增加确定性和环境风险。第一版不做。
- **调用 AI 音乐服务**：音乐性强但不可控、不可逐小节修改、需付费 key。以后作为新的配乐来源加入，与导入共用分析路径。
- **音频分析用 madmom / essentia**：madmom 基本停更，essentia 为 AGPL。选 librosa。

## 影响

- 取代架构设计"第一版只实现 manim"的前提，非目标中新增：歌词、变速曲、讲解视频卡点。
- api 进程常驻一个无头浏览器用于预览，需关注资源占用。
- 依赖体量增加（Chromium、librosa 带来的 scipy/numba），`make setup` 时间变长。
- import-linter 需为 `studio.timeline` 与 `engines.render.html` 增加"只依赖 config"的契约。
