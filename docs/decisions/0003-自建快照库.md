# 0003：用自建的内容寻址快照库做版本管理，不用 git

## 元信息

| 项 | 值 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-09-26 |
| 相关 | [架构设计 §3.3](../design/2026-09-26-architecture.md) |

## 背景

画布式交互需要每轮快照、回滚和对比。起初计划每个工作区一个 git 仓库，但 agent 开放了 Shell，可能自行执行 git 命令，破坏版本历史。

## 决定

快照是一份清单 `{路径: sha256}`，存在 SQLite 的 `snapshots` 表中；内容按哈希存到 `data/blobs/`。快照库位于工作区之外，agent 无法访问。回滚会新建快照，不改写历史。

## 考虑过的其他方案

- **每个工作区一个 git 仓库**：不选的原因：agent 可能篡改历史；需要依赖 git 命令；快照和数据库状态无法放在同一个事务里。
- **整目录复制**：不选的原因：没有去重，对比和回滚要遍历目录。
- **dulwich**：不选的原因：保留了 git 的复杂语义，收益不大。

## 影响

核心代码大约 200–300 行。越界检查和"用户编辑"检测都复用清单对比。工作区只有几十个文本文件，每轮全量扫描的开销可以忽略。
