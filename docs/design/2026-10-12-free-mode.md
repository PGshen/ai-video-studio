# 自由模式：直接创建的单阶段项目

状态：待批准（2026-10-12）。本文**新增**一种项目模式，不修改已批准的 [架构设计](2026-09-26-architecture.md) 与各子项目设计：多阶段项目（以下称"多阶段模式"）的流水线、阶段与行为全部不变。

## 1. 背景与目标

现在所有项目都要从选题池的想法卡片创建，并按阶段推进（讲解：`topic → narrative → (music) → animation_html`；短片、MV：`concept → produce`）。实际使用中常有更灵活的需求：给一个题目直接生成讲解视频、临时做一条主题短片。这时选题池、阶段拆分、定稿与上游约束都是负担。

**目标**

1. **直接创建**：项目页可以直接新建，不经过选题池；选题卡也能建自由项目。
2. **单阶段、过程自由**：整个项目只有一个对话环节完成所有事情；agent 可以读写整个工作区，不要求先有简报、叙事等前置文件，体验接近直接用 Claude Code。
3. **保留实时预览与成片**。

**不做**：自由项目与多阶段项目之间互相转换；创建后修改形态；讲解 + 导入音乐（现状本就不支持）；`timeline` schema、worker、渲染引擎的改动。

## 2. 已确认的决定

| 项 | 决定 |
|---|---|
| 形态何时确定 | 创建时选（讲解 / 短片 / MV）；预览与成片继续按项目类型读文件 |
| 「直接创建」入口 | 只给自由模式；多阶段项目仍从选题卡创建 |
| 选题卡 | 可以用来创建自由项目，卡片照旧写进 `notes/idea-card.md` |
| 成片前校验 | 不加额外关口；沿用 worker 的前置检查（渲染时缺什么报什么）与「成片定稿」的快照核对 |
| 联网 | 自由模式联网 |
| agent 工作方式 | 照用户说的做，没说清楚的先给简短方案再问；提示词只规定交付格式与引擎规则，不规定步骤顺序 |
| 实现方式 | 新增单阶段流水线（方案 1）；不采用"多阶段全部解锁"（方案 2）或"脱离阶段系统的裸项目"（方案 3） |

## 3. 项目模型

### 3.1 `ProjectKind.mode`

`stages/pipeline.py` 的 `ProjectKind` 增加字段 `mode: Literal["staged", "free"]`，默认 `staged`。

- `KIND_SETTING_KEYS` 加 `mode`；`kind_settings` 写入 `mode`；创建后只读，客户端 `settings` 里的同名字段照旧丢弃。
- `kind_from_settings`：`mode` 缺失或取值非法时按 `staged`（老项目无需迁移）。
- `video_kind`、`engine`、`narration`、`music_source` 的含义与取值不变。

### 3.2 可创建的自由形态

| 界面名 | `ProjectKind` | 流水线 |
|---|---|---|
| 自由讲解 | `html` + 有旁白 + `none` | `["free_explainer"]` |
| 自由讲解（带背景乐） | `html` + 有旁白 + `synth` | `["free_explainer"]` |
| 自由短片 | `html` + 无旁白 + `synth` | `["free_produce"]` |
| 自由 MV | `html` + 无旁白 + `import` | `["free_produce"]` |

- `build_pipeline`：`mode == "free"` 时按旁白有无返回 `["free_explainer"]` 或 `["free_produce"]`。
- `kind_errors` 增加：`mode == "free"` 且有旁白时 `music_source` 不能为 `import`。
- `valid_kinds()` 包含上表四种自由组合。
- `PRESETS` 增加三张卡片（自由讲解、自由短片、自由 MV），自由讲解的 `music_choices` 为 `("none", "synth")`。

### 3.3 创建接口

- `POST /projects` 接收 `mode`（缺省 `staged`）；校验与"任何副作用之前 422"的顺序沿用现状。
- `idea_id` 可选：给了就把卡片写到 `<pipeline[0]>/notes/idea-card.md`（即 `free_explainer/notes/…` 或 `free_produce/notes/…`），沿用现有规则。
- `GET /api/video-kinds` 返回三张自由卡片，带可用性与不可用原因（共用 `unavailable_reason`）。
- `ProjectOut` 暴露 `mode`（前端标记"自由"用）。

## 4. 自由阶段

### 4.1 两个阶段

阶段协议（`agent/stage.py` 的 `StageDefinition`）的 `system_prompt()`、`tools()`、`write_scope()` 不带项目参数，一个阶段名只能有一套提示词与工具。沿用现有惯例——形态差异大的拆阶段（`animation_html` / `produce`），差异小的在阶段内按工作区文件分流（`produce` 按有无 `music/source.*` 分短片与 MV）——新增两个阶段：

- `free_explainer`（界面名「自由讲解」）：有旁白。工作区有 `music/events.json`（或 `music/compose.py`）时按"讲解 + 背景乐"处理。
- `free_produce`（界面名「自由创作」）：无旁白；有 `music/source.*` 为 MV，否则为短片。

两者放在 `stages/free_explainer/`、`stages/free_produce/`，在 `main` 注册，后端与前端 `STAGE_TITLES` 同步。不改阶段协议。

### 4.2 共同属性

| 属性 | 取值 |
|---|---|
| `allow_web` | `True` |
| `workspaceless` | `False` |
| `reads()` | `[]`：没有上游，因此没有 stale、`upstream/` 阶段副本、回退建议 |
| `write_scope` | `writable=["*"]`（`fnmatch` 的 `*` 匹配 `/`，即整个工作区）；`tool_managed` 见 §4.3 |
| `prepare_turn` | 只把金样本复制到 `upstream/exemplar/`（`free_produce` 遇到 MV 时再复制歌词技法样本，与 `produce` 相同）；**不**生成 `upstream/timeline.json` |
| `artifact_dirs` | `free_explainer`：`narrative`、`music`、`animation`；`free_produce`：`music`、`animation` |
| `finalize_blockers` | `free_produce` 复用 `produce` 的检查；`free_explainer` 组合叙事检查（`narrative.json` 合法、配音与之一致）与场景检查（每个镜头有场景文件），有配乐时加配乐检查。共用函数移入 `stages.common` |
| `status_summary` | 讲解：镜头数、配音是否最新、场景覆盖、配乐状态；短片/MV：配乐渲染或歌曲分析状态、镜头覆盖 |

定稿只发生在「成片定稿」（`finalize-render`）：成片基于最新快照时，调用 `stage_flow.finalize` 并把项目标记完成；之后可「重新打开」。

### 4.3 可写范围

`tool_managed`（agent 不能直接写）：

- 配音：`narrative/timing.json`、`narrative/audio/**`
- 配乐：`music/music.wav`、`music/events.json`、`music/analysis.json`、`music/analysis.png`、`music/render.json`
- 上传：`music/source.<ext>`、`music/lyrics.lrc`
- 风格：`style/**`

`WriteScope` 没有排除列表；把 `style/**` 列进 `tool_managed` 能借用越界防线的"还原为本轮开始时内容"，让项目风格文件保持只读（没有工具会写它）。`uploads/` 由 `is_writable` 统一禁止，`upstream/`、`output/`、`.cache/` 不在扫描范围内。

### 4.4 提示词

结构：**自由模式公共部分 + 形态的交付约定**。

- 公共部分：照用户说的做；需求不清楚时先给简短方案（时长、要点、视觉方向）再问；用户只要求一部分就只做那部分；可以自由写笔记和大纲（建议 `notes/`）；改完用工具自查、预览。
- 交付约定：讲解为 `narrative.json` 结构、`validate_narrative`/`synthesize_tts` 用法、场景脚本契约、风格文件读法、可选背景乐；短片/MV 为 `music/compose.py` 或歌曲分析、`range.json`、`animation/shots.json`、场景契约。

**复用方式**：把现有 `narrative`、`animation_html`、`produce` 提示词中描述格式与契约的段落抽到 `stages/common/prompts/*.md`；多阶段提示词改为"阶段开场白 + 引用片段"，拼接结果与重构前**逐字一致**（测试锁定）；自由阶段引用同一批片段。与阶段绑定的说法（"读 `upstream/topic/brief.md`"、"你只能写 X"）不进入共享片段，留在各自开场白里。

## 5. 工具与时间轴

### 5.1 时间轴来源表

现在 `stages/common/scenes/helpers.load_timeline` 与 `render_music` 按 `ctx.stage == "produce"` 分支。改为在 `stages.common` 维护"阶段 → 时间轴来源"一张表：

| 阶段 | 来源 |
|---|---|
| `animation_html`、`music` | 读 `upstream/`（不变） |
| `produce`、`free_produce` | 即时构建，无旁白，`TimelineSources(produce=True)`（现有逻辑） |
| `free_explainer` | 即时构建，有旁白，读工作区顶层 `narrative/narrative.json` + `timing.json`；有 `music/events.json` 时叠加配乐层 |

`free_explainer` 下的 `render_music` 从顶层读不含配乐层的时间轴、写 `base_hash` 并做重定时校验——与 `api/music.py` 手动渲染的读法一致，worker 的 `base_hash` 检查因此对得上。

### 5.2 工具搬家

`synthesize_tts`、`validate_narrative` 及其依赖的 `narrative/schema.py` 移到 `stages/common/narration/`；`narrative` 阶段改为从那里 import，行为不变（满足"各阶段之间互不 import"）。场景、配乐、歌曲分析、联网工具已在 `common`。

### 5.3 工具清单

| 工具 | `free_explainer` | `free_produce` |
|---|---|---|
| 联网（`web_search`/`fetch_url` 或运行时原生） | ✓ | ✓ |
| `validate_narrative`、`synthesize_tts` | ✓ | — |
| `render_music` | ✓ | ✓（短片；MV 下按现状报错） |
| `analyze_music` | — | ✓（MV） |
| `validate_scenes_html`、`render_preview_html` | ✓ | ✓ |
| `suggest_upstream_change`、`check_brief`、`check_concept` | — | — |

各工具的 `stages={...}` 相应加入新阶段名。

### 5.4 api 中按阶段名判断的地方

- `api/animation_stage.animation_stage_of`：流水线含 `free_explainer` / `free_produce` 时返回它，渲染任务、`finalize-render`、`reopen`、场景检查随之生效。
- `api/scene_checks._CHECKED_STAGES` 加入两个新阶段。
- 歌曲与歌词上传：自由项目没有 `concept` 行，现有逻辑视为未定稿，允许上传，不改。
- 计划阶段全仓（含前端）搜索 `"produce"`、`"animation_html"` 等字面量补齐遗漏。

### 5.5 不改

worker（`worker_html` 按项目类型读顶层文件）、`timeline`、`engines`、`api/html_preview`、`api/music`、`api/music_import_meta` 的主体逻辑。

## 7. 测试

全部纳入 `make check`，测试先行。

- `stages/pipeline`：自由形态的流水线；非法组合（自由讲解 + 导入）；缺失 `mode` 按 `staged`。
- `api/projects`、`api/video_kinds`：创建自由项目（带/不带 `idea_id`）、卡片路径、`mode` 不可被客户端覆盖、422 先于副作用、三张自由卡片。
- 两个自由阶段：可写范围（`notes/x.md` 可写；`timing.json`、`style/STYLE.md`、`uploads/…` 不可写）、工具清单、`allow_web`、`prepare_turn` 只复制金样本、`status_summary`、`finalize_blockers`。
- 提示词：重构后 `narrative`、`animation_html`、`produce` 的提示词与重构前逐字相同（先以重构前文本为对照，确认后移除对照文件）。
- 时间轴来源：`free_explainer` 下场景工具与 `render_music` 从顶层读、有配乐时叠加配乐层；`produce`、`animation_html` 现有测试保持通过。
- 工具搬家：`narrative` 现有测试通过；import-linter 契约通过。
- api：自由项目的渲染任务、成片定稿、场景检查认识新阶段；自由 MV 可上传歌曲与歌词。
- worker：自由讲解工作区夹具通过现有前置检查（证明 worker 无需改动）。
- 前端（vitest）：`NewFreeProjectDialog`、自由卡片、`HtmlAnimationCanvas` 按形态的标签页与默认页、单阶段 `StageNav`、项目页「新建项目」入口。

**冒烟**（`make smoke`，真实模型，优先本机 Claude 订阅登录）：

- 自由讲解：给一个题目，第一轮应先给方案或提问而不直接产出；回复"按这个做"后产出 `narrative.json`、配音、场景并渲染出 `final.mp4`。
- 自由短片：一句话需求 → `compose.py`、`shots.json`、场景 → 成片。
- 自由 MV：复用 `test_music_video_smoke.py` 的歌曲夹具，验证到场景校验通过；完整成片作为同一用例的可选部分。

**手动验收**：`make dev` 后在浏览器走一遍新建 → 对话 → 预览 → 成片 → 定稿，截图。

## 9. 风险

| 风险 | 应对 |
|---|---|
| 抽取提示词片段时意外改变多阶段的提示词 | 逐字对照测试 |
| 自由讲解中改了叙事、重新配音后，场景或配乐与新时间轴不一致 | 场景工具与 `render_music` 即时构建时间轴会直接报出；worker 前置检查兜底；`status_summary` 提示配音/配乐是否最新 |
| `writable=["*"]` 让 agent 误删产物 | 每轮自动快照，可回滚；工具托管文件与 `style/` 仍受越界防线保护 |
| 自由 MV 的歌曲上传从 concept 挪到工作台画布 | 复用 `ImportMusicCanvas` 与现有上传接口，只放开 `allow-upload` |
