# 风格库重构设计

- 日期：2026-10-04
- 状态：待负责人审阅
- 取代：[ADR 0011 风格库采用 skill 形态目录](../../decisions/0011-风格库采用skill形态目录.md) 中「存 `style_presets` 表」的部分（其余约定保留）
- 关联：[架构设计](../../design/2026-09-26-architecture.md) §3.1 的 `style_presets` 表描述将过时；按红线不改 `docs/design/`，由负责人决定是否手动更新

## 1. 目标与背景

风格库现在是设置页里的一个 Tab：左侧按分类的按钮列表 + 右侧编辑器，纯 CRUD，没有 AI 参与，风格内容存在 SQLite 的 `style_presets` 表（JSON 列）。

本次重构的目标：

1. 风格库提升为侧边栏一级菜单（`/styles`），设置页移除对应 Tab。
2. 列表页：顶部筛选 + 新建按钮，卡片展示，分页。
3. 点击卡片，用右侧抽屉打开详情（只读）。
4. 卡片上有编辑按钮，点击后直接以编辑态打开抽屉。
5. 编辑布局沿用现有的「元信息 + 文件树 + 代码编辑器」，右侧新增一栏 AI 对话区，用对话来修改和调整风格。

### 已确认的决定

| 决定 | 内容 |
|---|---|
| AI 改动的落地方式 | AI 改的是**草稿**，用户确认「保存」后才成为正式版本；「放弃修改」即撤销，不做快照和回滚 |
| 存储 | 风格改为**纯磁盘目录**，SQLite 不再存风格 |
| 元数据 | 名称、简介、分类都放在 `STYLE.md` 的 frontmatter，AI 也能改 |
| 单人本地使用 | 不考虑多人并发编辑 |

### 为什么放弃「前端提交完整草稿」

最初的方案是每次发消息时前端把整包草稿交给后端，由后端渲染成临时目录给 agent。这样要传完整草稿，也要在轮次结束后取回，不优雅。把风格存成目录之后，草稿本身就是服务端的一个目录，agent 直接在上面工作，前端只通过文件接口读写。

## 2. 存储

```
data/styles/<id>/            已保存的正式版本
  STYLE.md
  references/*.md
  exemplars/*.json|md
data/style-drafts/<id>/      草稿工作副本，只在编辑时存在
  （结构同上）
```

- **id**：沿用旧表的 id 作为目录名，这样 `settings.default_style_preset_id` 和各项目 `settings.style_preset_id` 不需要重新映射；新建的风格用短随机 id。
- **frontmatter**：`name`、`description`、`category`。`name`、`description` 必填；`category` 缺省为「未分类」。
- **校验规则**（原样迁移，作用在目录上，纯函数）：
  - 名称非空且不超过 100 字符，且在所有风格中唯一（trim 后）。
  - `STYLE.md` 必须有 frontmatter，不超过 200000 字符。
  - 每个子目录不超过 30 个文件；文件名匹配 `^[\w.\-]+$`、不超过 80 字符、不以点开头、不重名。
  - `references/` 只允许 `.md`；`exemplars/` 只允许 `.json` 和 `.md`，`.json` 必须是合法 JSON。
  - 入口里出现的 `references/x`、`exemplars/y` 引用必须存在。
- **保存**：校验通过后，先把草稿复制到临时目录，再整体 rename 替换 `data/styles/<id>/`，避免写到一半失败留下残缺版本。
- **「已修改」**：比较草稿和正式版本的文件内容。
- **新建风格**：直接生成一份带模板的草稿；第一次保存之前在列表里标记为「未保存的新风格」（`is_new`），点开直接进编辑态；放弃时整个目录删除。（2026-10-04 修订，见文末）
- **列表**：扫描 `data/styles/`，返回摘要（id、name、category、description、引用数、金样本数、是否默认、是否有未保存草稿、最近修改时间）。筛选、排序和分页在前端做，与选题池一致。
- **默认风格**：仍存在 `settings` 表的 `default_style_preset_id`，不变。
- **创建项目**：直接复制 `data/styles/<id>/` 到项目 `style/`，复制后与风格库脱钩，行为不变。

### 迁移

- 一次性迁移：把 `style_presets` 表的行导出成目录，再删表。迁移方式（独立脚本 + 后续迁移删表，还是在 Alembic 迁移中一次完成）在实现计划里确定，要求可重复执行、导出后能核对数量。
- 旧项目风格导入脚本 `db/legacy_styles.py` 改成直接写目录，走同一套校验。

## 3. 后端 API

`/api/style-presets` 整体替换为 `/api/styles`：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/styles` | 摘要列表 |
| GET | `/api/styles/{id}` | 正式版本的完整内容 |
| POST | `/api/styles` | 新建：生成模板草稿，返回 id |
| POST | `/api/styles/{id}/duplicate` | 复制为新的正式版本 |
| DELETE | `/api/styles/{id}` | 删除正式版本和草稿；若是默认风格则清除默认设置 |
| POST | `/api/styles/{id}/draft` | 打开草稿：没有就从正式版本复制，已有则幂等返回 |
| GET | `/api/styles/{id}/draft/files` | 草稿文件树和已修改标记 |
| GET / PUT / DELETE | `/api/styles/{id}/draft/files/{path}` | 草稿文件的读、写、删 |
| POST | `/api/styles/{id}/draft/save` | 校验后覆盖正式版本；校验失败 422 并逐条列出错误 |
| DELETE | `/api/styles/{id}/draft` | 放弃草稿 |
| POST / GET | `/api/styles/{id}/sessions` | 创建、列出这套风格的对话会话 |

- 错误映射：404 不存在，422 校验失败，409 重名或有对话轮次正在运行。
- 草稿文件接口在这套风格有对话轮次运行时返回 409，与项目文件接口的行为一致。

## 4. agent 对话

- **`style` 阶段**（新增 `stages/style/`）：
  - 工作目录是这套风格的草稿目录，读写范围限定在该目录内。
  - 使用原生文件工具（遵循 ADR 0004），另外提供 `validate_style` 工具让 agent 随时自检。
  - 提示词写清风格目录结构、frontmatter 规则，以及「STYLE.md 要索引每个文件、写明什么时候读」的约定。
  - 默认不联网。
  - 默认模型沿用「通用」设置中的阶段默认模型，新增 `style` 一项。
- **`TurnRunner` 第三种模式**：工作目录绑定到指定目录，没有快照、上游同步和前言。同一套风格的对话轮次串行（`busy_key` 按风格 id）。
- **会话归属**：`sessions` 表新增可空列 `subject_id`（新迁移）。`create_session` 把同一 `项目 + 阶段 + subject_id` 下的其他会话置为非活动，避免不同风格的会话互相干扰。发消息、取消、继续、SSE 流沿用现有会话接口。
- **事件**：agent 写文件后沿用 `workspace_changed`，前端据此刷新草稿。

## 5. 前端

### 入口与路由

- 侧栏 `navMain` 在「项目」和「设置」之间新增「风格库」（`/styles`）；设置页移除风格库 Tab。
- `/settings/styles` 重定向到 `/styles`。
- 抽屉状态放在 URL query：`/styles?style=<id>&mode=view|edit`。
- 新增 `features/styles/`，删除 `StylePresetsPanel.vue` 和 `StylePresetEditor.vue`。对话组件继续从 `components/session/` 引入，遵守 ESLint 分层规则。

### 列表页

- 顶部筛选栏：关键词、分类 Badge 筛选、「仅看默认」、「新建风格」按钮。
- 卡片网格借用选题池 `IdeaGrid` 的模式：名称、分类、简介摘要、引用数和金样本数，以及「默认」和「有未保存草稿」标记，卡片上有编辑按钮。
- 分页复用 `ListPager` 和 `pagination.ts`。
- 筛选和排序逻辑放进 `styleView.ts`（纯函数，配 `.spec.ts`）。

### 抽屉

- 使用现有 `Sheet`，右侧滑出，宽度约 `min(96vw, 1400px)`。
- **详情态**：名称、分类、简介 + 只读文件树和代码查看；按钮「编辑」「设为默认」「复制」「删除」。
- **编辑态**：
  - 左侧：名称、分类、简介表单 + 文件树 + 代码编辑器（布局与现在一致）。
  - 右侧：约 24rem 的对话区，复用 `SessionPanel`、模型切换和会话选择。
  - 底部：「保存」「放弃修改」。
- 点卡片上的编辑按钮，直接以编辑态打开并打开草稿。

### 草稿数据流

- 进入编辑态时调用「打开草稿」，之后所有文件操作都走草稿文件接口，前端不持有整包草稿。
- 编辑器输入后 600ms 防抖写草稿文件，并显示草稿保存状态。
- 名称、分类、简介表单读写 `STYLE.md` 的 frontmatter，解析和回写放进 `styleFrontmatter.ts`（纯函数加测试）；AI 改了 frontmatter 后表单从草稿重新派生。
- 对话轮次运行期间，编辑器和表单只读，轮次结束后刷新。
- 收到 `workspace_changed` 或文件类 tool_result 时，让草稿的文件树和当前文件的查询失效，沿用 `useSessionStream` 现有机制。
- 关闭抽屉不丢草稿；保存和放弃都是显式操作；卡片显示「有未保存草稿」。
- 保存校验失败（422）的错误逐条显示在底部。

### 对话作用域

- `sessionScope.ts` 新增 `{kind: 'style', styleId}`，同步修改 `queries.ts` 中会话相关的 key 和创建分支，以及 `useEnsureSession`。
- 设置页「通用」中的阶段默认模型新增 `style`。
- 工具渲染为 `validate_style` 补一个展示。

### 组件拆分

原 440 行的编辑器拆成 `StyleDrawer`、`StyleDetailView`、`StyleEditView`、`StyleMetaForm`、`StyleFileTree`，每个 `.vue` 不超过 250 行。

## 6. 错误处理

- 保存校验失败：422 + 逐条错误，不改变正式版本，草稿保持不动。
- 轮次运行时用户或其他请求写草稿：409，前端提示「AI 正在修改，请稍候」。
- agent 写入越出草稿目录：由现有的读写范围守卫拦截。
- agent 产生的草稿不合法：不拦截（草稿允许处于不合法状态），在保存时统一校验；`validate_style` 工具让 agent 有机会自检。
- 迁移出现重名或不合法旧数据：迁移报告逐条列出，不静默丢弃。

  - API：`/api/styles` 全部接口，包括 409 和 422。

## 9. 交付拆分

实现计划将分四个阶段，每个阶段都能独立跑通 `make check`：

1. **后端存储迁移**：风格改为目录存储，新增 `/api/styles` 和草稿接口，迁移旧数据，项目创建和导入脚本改读目录。
2. **前端新页面**：侧栏菜单、列表页、抽屉、详情态和编辑态（暂不含对话）。
3. **agent 与会话**：`sessions.subject_id` 迁移、`style` 阶段、`TurnRunner` 第三种模式、风格会话接口。
4. **对话接入与收尾**：前端接入对话区，补 ADR 和文档，浏览器验证。

## 10. 不做的事

- 不做草稿或正式版本的历史记录与回滚；撤销靠「放弃修改」。
- 不做多人协作编辑和冲突合并。
- 不做服务端筛选和分页，风格数量少，前端处理即可。
- 不让 agent 联网。

## 修订记录

- 2026-10-04（T7 浏览器走查）：原设计写「新建风格保存之前不出现在列表里」。实测发现关掉抽屉后这份草稿就成了找不回的孤儿目录（误点遮罩、或 AI 已经写了内容都会丢）。改为：从未保存的新风格也出现在列表里，标记 `is_new`，点开直接进编辑态，放弃时整个目录删除；名称唯一性仍只在已保存的风格之间检查。
