## narrative.json 的结构

```json
{
  "scenes": [
    {
      "id": "s-hook",
      "narration": "你有没有想过，为什么……",
      "visual_intent": "这一镜要让观众看到什么、传达什么",
      "beats": [
        {
          "cue_text": "你有没有想过，",
          "visual_action": "屏幕中央浮现问题文字",
          "emphasis": "问题本身",
          "transition": "reveal"
        }
      ]
    }
  ]
}
```

- **`id`**：稳定的 slug（如 `s-hook`、`s-explain-1`），整份文档里唯一。
  它是动画代码文件名（`animation/scenes/<id>.py`）、音频文件名和下游变更
  摘要的键——**已经定稿过的镜头不要随便改 id**，改了会被当成"删除旧镜头
  + 新增镜头"，下游动画代码要整段重写。
- **`narration`**：这一镜的完整旁白，就是要被念出来的原文。写成口语，
  一句话别太长；不要写括号里的舞台说明、镜头提示，那些属于
  `visual_intent`/`visual_action`。
- **`visual_intent`**：这一镜的画面意图——观众该看到什么、理解什么，而不是
  逐帧指令。动画阶段读它决定整体构图，所以要带上这一镜的主要配色（底色和主要对象的颜色）。
- **`beats[]`**：把旁白切成按时间顺序的若干小段，每段对应一次画面动作。

### beats 的四个字段

- **`cue_text`**：这个 beat 对应的旁白原文片段，**连标点一起原样截取**。
  所有 beat 的 `cue_text` 按顺序首尾相接，必须刚好拼出 `narration`：校验
  只忽略空白，以及全角/半角标点的写法差异（`，` 与 `,` 视为相同），不会
  忽略标点本身，更不允许多字、少字、换字、调换顺序。它同时是配音后做时间
  对齐的依据：对齐用它在逐字时间戳里定位每个 beat 的起止时间。
- **`visual_action`**：这个 beat 里画面上发生的一次具体动作（什么出现、
  移动、变形、消失）。写"做什么"，不写代码；涉及颜色时写明是哪种色、表达什么语义
  （如"警示橙标出临界点"），不要只写"高亮"。
- **`emphasis`**：这个 beat 要观众抓住的重点，一句话。
- **`transition`**：这个 beat 的画面相对上一个 beat 怎样衔接，只能取下面五个值：
  - `continue`：沿用上一个 beat 的画面继续叠加/推进，不换主体；
  - `transform`：把上一个 beat 的主体变形成新的形态（同一个元素的演变）；
  - `reveal`：在当前画面上新揭示一个元素或信息，原有元素保留；
  - `replace`：上一个 beat 的主体让位，被一个新的主体取代；
  - `exit`：主体退场，画面收束（通常用在镜头或段落的最后一个 beat）。

### beat 拆分的粒度

- 一个 beat 承载**一次**画面动作、**一个**要点。旁白里出现新概念、
  转折、数字、对比时，通常就是新 beat 的起点。
- 太碎（一个 beat 只有两三个字）会让画面动作来不及演完；太粗（整段
  旁白只有一个 beat）会让动画阶段没有节奏依据。一个 beat 大致对应 1–3 秒
  的语音（约 5–20 个汉字）。
- 在标点处切分，让 `cue_text` 以自然的停顿结束，不要在词语中间切开。
